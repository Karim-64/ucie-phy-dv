Black-Box Verification Specification

Timer_SBTX IP — UCIe Sideband Transmitter Support

1. Purpose and Functional Overview

The Timer_SBTX IP is a programmable timer used in the UCIe Sideband Transmitter (SBTX) subsystem.

The timer is intended to provide a configurable waiting interval between consecutive 64-bit message phases when PMO support is unavailable. A 32-cycle low interval is required between consecutive message phases.

The IP receives a start request and generates an alarm indication when the programmed counting interval reaches its terminal count. The alarm is used by the surrounding system to identify the required timing boundary.

The verification environment must treat the IP as a black box. Verification must be based exclusively on the documented interface, parameters, reset behavior, timing requirements, and externally observable outputs. The internal RTL implementation must not be accessed or assumed.

4. Functional Behavior

4.1 Reset Behavior

When rst_n is asserted low, the timer must asynchronously return to its initial state.

The elapsed count is cleared.

The timer becomes idle.

alarm must be low after the reset has taken effect.

Reset must operate independently of the clock edge.

After reset is released, the timer must remain idle until a valid start request is sampled.

4.2 Start Behavior

A high start level initiates counting when the timer is idle and the reset is inactive.

The start request is sampled on the rising edge of clk.

A start request does not itself indicate timer completion.

Once counting has started, the timer continues counting on subsequent rising clock edges even if start returns low.

If start remains high during an active counting operation, it must not restart or clear the current operation.

The timer must continue its normal operation without requiring start to remain asserted.

4.3 Counting and Terminal-Count Behavior

The timer advances its elapsed-count state on rising clock edges while a counting operation is active.

The configured terminal-count value is NO_OF_CYCLES - 1.

When the elapsed count reaches the terminal-count value, alarm is asserted.

The timer returns to its initial count and becomes idle at the terminal-count handling edge.

When the count returns to its initial value, alarm becomes low.

The timer must not generate an additional terminal-count event during an idle period without a new start request.

For the default configuration, the terminal-count value is 31.

Important timing clarification: The terminal-count indication is derived from the current count state. Consequently, the assertion and deassertion of alarm must be checked against the observed count progression and clock edges, rather than assuming that it is a registered one-cycle-later completion pulse.

4.4 Idle Behavior

When the timer is idle and no start request is accepted:

The elapsed count remains at its initial value.

alarm remains low.

No new counting operation begins spontaneously.

4.5 Reset During Counting

If rst_n is asserted while a counting operation is active:

The active operation is aborted.

The timer immediately returns to its initial state.

alarm becomes low after reset takes effect.

No completion event from the aborted operation may be reported after reset has cleared the timer.

Following reset release, a new start request is required to initiate another operation.
