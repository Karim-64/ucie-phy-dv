# Priority Encoder (`Priority_Encoder_SBTX`) Black-Box Functional Specification

## 1. Overview / Architectural Purpose

The **Priority Encoder (`Priority_Encoder_SBTX`)** is an ingress arbitration and multiplexing block residing within the Logical Clock (`LCLK`) domain of the Universal Chiplet Interconnect Express (UCIe) Sideband Transmitter (`SBTX`) subsystem. 

Within the UCIe Physical Layer and Die-to-Die (D2D) Adapter architecture, sideband traffic is generated by two distinct local sources that share a single physical sideband serialization link:
* **The Physical Layer Controller (PHY / Encoder path):** Generates link training, initialization, and physical layer management messages.
* **The D2D Adapter Decoder (`D2D` path):** Forwards remote register access requests (RARs), completions, and D2D layer parameter/state management messages arriving over the Raw Die-to-Die Interface (RDI).

The Priority Encoder sits directly upstream of the Clock Domain Crossing (CDC) Gray Asynchronous FIFO that bridges the `LCLK` domain and the Sideband Clock (`SB_CLK`) serialization domain. Its primary architectural purpose is threefold:
1. **Contention Resolution:** Arbitrates simultaneous write requests between the PHY Controller and D2D Decoder, enforcing fixed priority favoring the PHY Controller during single-cycle contention.
2. **Multi-Phase Message Atomicity:** UCIe sideband messages with data payloads consist of a 64-bit Header Phase followed by a 64-bit Data Phase. When a granted source initiates a message containing a data phase, the block locks arbitration to that source across the consecutive transfer cycles to prevent interleaving partial packets from the competing source.
3. **Bufferless Flow Control & Metadata Tagging:** Rather than instantiating internal packet buffers, the block utilizes a lightweight retry/resend notification mechanism (`D2D_Resend_Req` and `PHY_Resend_Req`) to instruct rejected sources to re-issue their transactions. Alongside the 64-bit message payload, it generates and forwards sideband control markers (`Data_Marker`, `D2D_PHY_Marker`, `Comp_Marker`) into the CDC FIFO to govern downstream serialization framing and credit return accounting.

## 2. Interface Description (Port Table)

The block is parameterized by `DATA_WIDTH` (defaulting to `64` bits) and operates entirely within a single synchronous clock domain (`CLK`) with an active-low asynchronous reset (`RST_n`).

| Port Name | Direction | Width | Clock / Reset Domain | Functional Description |
| :--- | :--- | :--- | :--- | :--- |
| `CLK` | Input | 1 | `LCLK` | Primary system clock (Logical Clock domain). All sequential arbitration grants and resend requests are registered on the rising edge. |
| `RST_n` | Input | 1 | `RST_n` (Async) | Active-low asynchronous reset. Clears all arbitration grants, priority locks, and resend request outputs. |
| `PHY_En` | Input | 1 | `CLK` | Request/Valid indicator from the PHY Controller requesting to enqueue a message into the downstream CDC FIFO (aliased as `Encoder_Mess_Valid` at the subsystem level). |
| `D2D_En` | Input | 1 | `CLK` | Request/Valid indicator from the D2D Decoder requesting to enqueue a remote D2D message into the downstream CDC FIFO. |
| `Data_Marker_PHY` | Input | 1 | `CLK` | Indicates that the incoming PHY Controller message is a multi-phase packet containing a subsequent data phase. |
| `Data_Marker_D2D` | Input | 1 | `CLK` | Indicates that the incoming D2D Decoder message is a multi-phase packet containing a subsequent data phase. |
| `Comp_Marker_D2D` | Input | 1 | `CLK` | Indicates that the incoming D2D Decoder message is a Completion packet (which does not consume or return D2D credits). |
| `PHY_Data` | Input | `DATA_WIDTH` (64) | `CLK` | 64-bit message phase payload (Header or Data phase) driven by the PHY Controller. |
| `D2D_Data` | Input | `DATA_WIDTH` (64) | `CLK` | 64-bit message phase payload (Header or Data phase) driven by the D2D Decoder. |
| `FIFO_WR` | Output | 1 | `CLK` | Write enable strobe driven to the downstream CDC Asynchronous FIFO. Asserted whenever a source holds an active arbitration grant. |
| `FIFO_Data` | Output | `DATA_WIDTH` (64) | `CLK` | 64-bit multiplexed payload bus driven to the downstream CDC Asynchronous FIFO. |
| `Data_Marker` | Output | 1 | `CLK` | Metadata tag written to the CDC FIFO indicating the current entry belongs to a message with a data phase (used by downstream TX serializer and credit handler). |
| `D2D_PHY_Marker` | Output | 1 | `CLK` | Metadata tag written to the CDC FIFO identifying the origin of the current entry (`1'b1` = D2D Decoder, `1'b0` = PHY Controller) for credit return filtering. |
| `Comp_Marker` | Output | 1 | `CLK` | Metadata tag written to the CDC FIFO indicating the current entry is a D2D Completion message (`1'b1` = Completion, `1'b0` = Non-Completion). |
| `D2D_Resend_Req` | Output | 1 | `CLK` | Registered flow-control flag notifying the D2D Decoder that its request in the previous cycle was rejected due to simultaneous PHY contention or an active priority lock. |
| `PHY_Resend_Req` | Output | 1 | `CLK` | Registered flow-control flag notifying the PHY Controller that its request in the previous cycle was rejected due to an active priority lock held by the D2D path. |

## 3. Operational Modes & Data Flow

The block's operation is governed by a two-stage split between **arbitration decision (Cycle $N$)** and **datapath multiplexing (Cycle $N+1$)**. Enable requests (`PHY_En`, `D2D_En`) and data markers (`Data_Marker_PHY`, `Data_Marker_D2D`) are evaluated on the rising edge of `CLK` in Cycle $N$ to establish the active channel grant for Cycle $N+1$, during which the corresponding payload and control markers are combinationally routed to the FIFO outputs.

### 3.1 Operating Modes & Arbitration Rules (Unlocked State)

When no multi-cycle priority lock is active, the block evaluates `{PHY_En, D2D_En}` at each rising clock edge and transitions into one of four operational states for the following clock cycle:

1. **Idle Mode (`PHY_En = 0`, `D2D_En = 0`):**
   * Neither source requests access.
   * On the following cycle ($N+1$), `FIFO_WR`, `FIFO_Data`, `Data_Marker`, `D2D_PHY_Marker`, `Comp_Marker`, `D2D_Resend_Req`, and `PHY_Resend_Req` are all driven to `0`.

2. **D2D Exclusive Mode (`PHY_En = 0`, `D2D_En = 1`):**
   * The D2D Decoder is granted the channel.
   * On Cycle $N+1$, `FIFO_WR` asserts (`1'b1`), `D2D_PHY_Marker` asserts (`1'b1`), and the outputs combinationally pass through the D2D inputs: `FIFO_Data = D2D_Data`, `Data_Marker = Data_Marker_D2D`, and `Comp_Marker = Comp_Marker_D2D`.
   * If `Data_Marker_D2D` was `1'b1` at the sampling edge of Cycle $N$, the arbiter engages the **D2D Priority Lock** starting in Cycle $N+1$.

3. **PHY Exclusive Mode (`PHY_En = 1`, `D2D_En = 0`):**
   * The PHY Controller is granted the channel.
   * On Cycle $N+1$, `FIFO_WR` asserts (`1'b1`), `D2D_PHY_Marker` de-asserts (`1'b0`), `Comp_Marker` is forced to `1'b0`, and the outputs combinationally pass through the PHY inputs: `FIFO_Data = PHY_Data` and `Data_Marker = Data_Marker_PHY`.
   * If `Data_Marker_PHY` was `1'b1` at the sampling edge of Cycle $N$, the arbiter engages the **PHY Priority Lock** starting in Cycle $N+1$.

4. **Simultaneous Contention Mode (`PHY_En = 1`, `D2D_En = 1`):**
   * The PHY Controller is strictly prioritized over the D2D Decoder.
   * On Cycle $N+1$, the PHY Controller is granted the channel (identical datapath routing to PHY Exclusive Mode), and `D2D_Resend_Req` is asserted (`1'b1`) to notify the D2D Decoder that its transfer was rejected.
   * If `Data_Marker_PHY` was `1'b1` at the sampling edge of Cycle $N$, the arbiter engages the **PHY Priority Lock** starting in Cycle $N+1$.

### 3.2 Multi-Cycle Data Transfer & Priority Lock Sequence

When a granted source asserts its respective `Data_Marker` input during an unlocked arbitration cycle (Cycle $N$), the block enforces a deterministic two-cycle lock window across Cycles $N+1$ and $N+2$ to guarantee atomic transfer of both the 64-bit Header Phase and 64-bit Data Phase:

| Cycle | Event / Phase | Input Sampling (at Rising Edge) | Output Behavior (During Cycle) |
| :--- | :--- | :--- | :--- |
| **Cycle $N$** | **Request & Lock Trigger** | Winning source asserts `*_En = 1` and `Data_Marker_* = 1`. | Outputs reflect the *previous* cycle's grant (e.g., Idle). |
| **Cycle $N+1$** | **Lock Cycle 1 (Header Phase)** | Priority Lock is active. New `PHY_En` / `D2D_En` requests are ignored for grant updates. Winning source drives Header Phase on `*_Data`. | `FIFO_WR = 1`. Multiplexer routes winning source's Header Phase (`*_Data`) and control markers to the FIFO. |
| **Cycle $N+2$** | **Lock Cycle 2 (Data Phase)** | Priority Lock remains active. Winning source drives Data Phase on `*_Data`. Lock expires at the end of this cycle and channel grant resets to Idle (`NONE`). | `FIFO_WR = 1`. Multiplexer routes winning source's Data Phase (`*_Data`) and control markers to the FIFO. |
| **Cycle $N+3$** | **Post-Lock Cooldown (Idle)** | Priority Lock is cleared (`0`). Arbiter is ready to sample new requests at the end of Cycle $N+3$. | `FIFO_WR = 0`, `FIFO_Data = 0`, all output markers = `0`. (Mandatory 1-cycle idle bubble after any locked two-phase transaction). |

## 4. Handshaking & Flow Control

### 4.1 Input Consumption & Pipeline Alignment
* **1-Cycle Grant Latency (Enable-Before-Data Pacing):** Because the output multiplexer is controlled by the registered grant decision while the data buses (`PHY_Data`, `D2D_Data`) and marker outputs (`Data_Marker`, `Comp_Marker`) pass through combinationally, upstream transmitters must adhere to a 1-cycle skewed timing relationship:
  * For a **single-phase (header-only) message**, the source asserts `*_En` (with `Data_Marker_* = 0`) in Cycle $N$, and must present the valid 64-bit Header payload on `*_Data` (and `Comp_Marker_D2D`, if applicable) during Cycle $N+1$.
  * For a **two-phase (header + data) message**, the source asserts `*_En` and `Data_Marker_* = 1` in Cycle $N$ to acquire the lock, presents the 64-bit Header Phase on `*_Data` in Cycle $N+1$, and presents the 64-bit Data Phase on `*_Data` in Cycle $N+2$. Note that `Data_Marker` at the FIFO output combinationally tracks the selected `Data_Marker_*` input during Cycles $N+1$ and $N+2$.
* **Post-Lock Turnaround Bubble:** At the conclusion of a locked two-phase transfer (end of Cycle $N+2$), the arbiter unconditionally clears its active grant to Idle (`NONE`) rather than immediately sampling `PHY_En` or `D2D_En`. Consequently, `FIFO_WR` is guaranteed to de-assert for at least one clock cycle (Cycle $N+3$) following any two-phase packet before a new grant can take effect in Cycle $N+4$.

### 4.2 Resend Request Protocol (`D2D_Resend_Req` & `PHY_Resend_Req`)
The block does not stall upstream pipelines via combinational ready/grant handshakes; instead, it issues registered resend requests on the cycle following a rejected request:
* **`D2D_Resend_Req` Assertion Conditions:** Asserts (`1'b1`) in Cycle $k+1$ if, during Cycle $k$:
  1. Both `PHY_En` and `D2D_En` were simultaneously asserted (`2'b11`) — regardless of lock state, **OR**
  2. Only `D2D_En` was asserted (`2'b01`) while the Priority Lock was active (`1'b1`) and the lock was held by the PHY Controller.
* **`PHY_Resend_Req` Assertion Conditions:** Asserts (`1'b1`) in Cycle $k+1$ if, during Cycle $k$:
  1. Only `PHY_En` was asserted (`2'b10`) while the Priority Lock was active (`1'b1`) and the lock was held by the D2D Decoder.
* **De-assertion & Retry Rule:** Both resend signals default to `1'b0` on any cycle where their respective trigger condition is not met. When an upstream requester observes its `*_Resend_Req` asserted, it must maintain or re-assert its request after the resend flag de-asserts.

### 4.3 Downstream FIFO Interface
* The downstream interface is a unidirectional push interface (`FIFO_WR`, `FIFO_Data`, `Data_Marker`, `D2D_PHY_Marker`, `Comp_Marker`).
* There is no backpressure (`Full` flag) input from the Gray Asynchronous FIFO; the downstream FIFO is architecturally sized (8 entries deep) to absorb worst-case active and training bursts without overflowing.

## 5. Dynamic Reconfiguration & Abort Mechanisms

* **Immunity to Mid-Transaction Preemption:** Once a two-cycle Priority Lock is established (in Cycle $N+1$ and Cycle $N+2$), the arbitration state machine ignores `PHY_En` and `D2D_En` for grant selection. A higher-priority PHY request arriving during Cycle $N+1$ of a D2D two-phase transfer cannot preempt or corrupt the D2D Data Phase in Cycle $N+2$; instead, `PHY_Resend_Req` is asserted in Cycle $N+2$.
* **Mid-Lock Request De-assertion:** During a locked two-phase transfer, the granted source is permitted to de-assert its `*_En` signal after Cycle $N$. Because the lock sustains the channel grant internally across Cycles $N+1$ and $N+2$, de-asserting `*_En` during the lock window does not abort the transaction or de-assert `FIFO_WR`.
* **No Mid-Packet Abort / Flush Pin:** The block does not implement a dedicated synchronous flush or abort pin. Once a 1-cycle or 2-cycle grant is latched, it runs to completion unless `RST_n` is asserted.
* **Contention Edge Case During D2D Lock:** If the D2D Decoder holds an active Priority Lock and both `PHY_En` and `D2D_En` assert simultaneously (`2'b11`) during the lock window, the block asserts `D2D_Resend_Req` (`1'b1`) and keeps `PHY_Resend_Req` low (`1'b0`).

## 6. Reset & Exception Handling

* **Asynchronous Reset (`RST_n = 1'b0`):**
  * Immediately upon assertion of `RST_n = 1'b0` (independent of `CLK`), the internal arbitration state is cleared to Idle (`NONE`), the priority lock and cycle counter are cleared to `1'b0`, and both `D2D_Resend_Req` and `PHY_Resend_Req` are asynchronously driven to `1'b0`.
  * Because the output datapath multiplexer is combinational and gated by the active grant state, clearing the grant state immediately forces all FIFO outputs (`FIFO_WR`, `FIFO_Data`, `Data_Marker`, `D2D_PHY_Marker`, `Comp_Marker`) to `0`.
* **Idle Gaps & Stall Behavior:**
  * Whenever both `PHY_En` and `D2D_En` are de-asserted while unlocked, or during the mandatory 1-cycle cooldown following a two-phase lock release, the block cleanly parks in the Idle state with `FIFO_WR = 1'b0` and all data/marker outputs driven to zero, preventing spurious writes to the CDC FIFO.
* **Safe Default State Handling:**
  * All case statements governing priority decoding and output multiplexing include explicit `default` branches. Any unmapped or uninitialized two-bit priority state safely resolves to the Idle (`NONE`) state on the next clock edge and drives all combinational FIFO outputs to `0`.
