# uvm_gen

Generates a single-agent UVM verification environment (interface, config
objects, sequencer/driver/monitor, agent, scoreboard, environment, base
test, tb_top, run.do) from one XML spec file. The output structure and
SystemVerilog conventions reproduce the `mem` reference environment this
tool was built from.

## Usage

```bash
python3 generate_uvm.py --config spec.xml --out-dir ./generated
python3 generate_uvm.py --config spec.xml --out-dir ./generated --dry-run   # validate + preview only
python3 generate_uvm.py --config spec.xml --out-dir ./generated --force    # overwrite existing output
```

Output lands at `<out-dir>/<agent_name>/...`.

## XML schema

See `examples/mem_spec.xml` for a complete example (it regenerates the
original `mem` reference almost exactly — see "Fidelity check" below).

```xml
<uvm_env name="agent_name">
  <parameters>
    <parameter name="PARAM_NAME" value="literal_value"/>
    <!-- 0+ parameters; threaded through the package, interface and virtual-if refs -->
  </parameters>

  <clock name="clk"/>  <!-- required -->

  <signals>  <!-- at least one "drv" and one "mon" signal required -->
    <signal name="sig_name" width="N_or_param_name" direction="drv|mon"/>
  </signals>

  <dut>  <!-- optional: omit to leave DUT instantiation out of tb_top -->
    <module_name>MyDut</module_name>
    <instance_name>dut</instance_name>  <!-- optional, defaults to "dut" -->
    <port dut_port="dut_port_name" signal="signal_name_or_clock_name"/>
    <!-- one per DUT port you want wired; doesn't have to cover every signal -->
  </dut>

  <env>
    <has_scoreboard>true|false</has_scoreboard>  <!-- optional, defaults to true -->
    <has_subscriber>true|false</has_subscriber>  <!-- optional, defaults to true -->
  </env>
</uvm_env>
```

Rules enforced by the parser before anything is written:
- `direction="drv"` signals become `rand` sequence-item fields, driven via
  the interface's `drv_cb` clocking block.
- `direction="mon"` signals become non-`rand` fields, sampled via `mon_cb`.
- Optional `depth="N"` on a `<signal>` makes it a packed 2D array
  `logic [N-1:0][width-1:0]` (e.g. `width="8" depth="64"` -> `[63:0][7:0]`).
  `depth` is an integer literal or a declared parameter, like `width`.
  The subscriber samples only the first and last element of array signals.
  Unpacked arrays are not supported. See `examples/demux_spec.xml`.
- A signal's `width` is either an integer literal or the name of a declared
  `<parameter>` — anything else is rejected.
- No duplicate parameter/signal/DUT-port names; no signal name collides
  with the clock name.
- Every `<dut><port signal="...">` must reference either the clock name or
  a declared signal (typos are caught, not silently generated).

## Scope (v1, by design)

- **One agent per environment.** No multi-agent/multi-interface XML — this
  may be revisited later, but each run produces one self-contained agent
  environment.
- **Generic coverage subscriber.** A `<name>_subscriber` (uvm_subscriber with
  one coverpoint per signal, default binning, `auto_bin_max = 16` for
  multi-bit fields) is generated by default and wired to the agent's
  analysis port. It is deliberately semantics-free; `iff` gates and
  crosses are DUT-specific and left as a TODO. Disable with
  `<has_subscriber>false</has_subscriber>`.
- **Scoreboard and base_sequence are TODO-stubs**, same as the reference —
  no reference-model logic is invented, since that's DUT-specific.
- **Active by default.** `active_passive_agents[name] = UVM_ACTIVE` is
  hardcoded in the generated `base_test`, matching the reference; there's
  no passive-mode XML toggle yet.
- **Questa/ModelSim only** for `sim/run.do` (`vlib`/`vlog`/`vsim`).

## Fidelity check

`examples/mem_spec.xml` was written to reproduce `mem.zip`'s `mem`
environment. Diffing the generated output against the original files
(ignoring line-ending differences — the originals are CRLF) shows the
only semantic delta is that `mem_subscriber` is the generic version (no hand-written `iff`/cross coverage). Every class
structure, phase method, config_db call, signal wiring, and the DUT
instantiation in `tb_top.sv` match exactly.

## Project layout

```
generate_uvm.py          CLI entry point
uvm_gen/
  model.py                Dataclasses: UvmEnvSpec, SignalSpec, ParamSpec, DutSpec, DutPortSpec, EnvFlags
  xml_parser.py            XML -> UvmEnvSpec, with validation (SpecError on anything malformed)
  renderer.py               UvmEnvSpec -> rendered files via Jinja2 templates
templates/                 One .j2 per generated file, mirroring mem/'s folder layout
examples/mem_spec.xml      Reference example (regenerates the mem/ environment)
generated/                 Output of the fidelity-check run (safe to delete/regenerate)
```
